# Contributing to the Data Science Portfolio

Thank you for your interest in improving this educational portfolio. Contributions should improve reproducibility, documentation, model evaluation, transparency, or responsible use of data.

## Before contributing

- Read the [README](README.md), [Code of Conduct](CODE_OF_CONDUCT.md), and [Security Policy](SECURITY.md).
- Only include public, appropriately licensed, synthetic, or explicitly authorized datasets.
- Never commit passwords, API tokens, personal records, financial account information, private datasets, or confidential business data.
- Distinguish simulated case studies from verified production deployments or real business outcomes.
- Avoid claiming model accuracy, uplift, fairness, or performance improvements that were not measured.

## Useful contributions

- Fix broken links, unclear descriptions, setup steps, or documentation errors.
- Improve dataset descriptions, preprocessing explanations, and feature definitions.
- Add reproducible train/validation/test workflows, tests, or evaluation examples.
- Document leakage risks, class imbalance, threshold selection, bias limitations, and model tradeoffs.
- Suggest responsible enhancements to churn prediction, credit risk, forecasting, fraud detection, marketing models, or recommendation systems.

## Contribution workflow

1. Check existing issues and open one for major changes when appropriate.
2. Create a descriptive feature branch.
3. Make focused changes without removing unrelated projects or evidence.
4. Run the relevant project commands described in its documentation.
5. Record the actual evaluation method, dataset source, random seed, results, and limitations where applicable.
6. Submit a pull request with an overview, reproduction steps, tests performed, and any data or ethical considerations.

Do not present planned model validations as completed tests.

## Security and privacy

Use the private reporting guidance in [SECURITY.md](SECURITY.md) for sensitive vulnerabilities or exposed data. Never publish those details in a public issue.
